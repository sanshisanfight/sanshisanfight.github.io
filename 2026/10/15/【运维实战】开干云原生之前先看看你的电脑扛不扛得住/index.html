【运维实战】开干云原生之前，先看看你的电脑扛不扛得住

发表于2026-10-15|更新于2026-10-15|云原生运维基础设施
|总字数:1.8k|阅读时长:6分钟|浏览量:

想在家搞一套 K8s 集群练手，第一步不是装软件，是算账。

我这台机器 12 核 32GB，看着挺唬人，结果一查内存：总 31.8GB，空闲只剩 3.7GB。占了 88%。

就这 3.7GB，我连一台像样的虚拟机都开不出来，更别提三节点 K8s 集群了。

这篇文章记录整个环境评估过程，以及我踩到的第一个坑。

一、先摸清家底

盲目开始是运维新人的通病。动手之前，先把机器的真实状态摸清楚。

看 CPU：够用

12 个逻辑核。查 CPU 型号用注册表：

坑点：wmic 命令在这个环境里被安全策略拦截了，报”Program blocked by security policy”。老教程里清一色用 wmic cpu get...，现在很多环境已经跑不通。改用注册表读取或 PowerShell 的 Get-CimInstance 更稳。

看内存：这是拦路虎

输出：

31.8GB 里被占了 28GB。这是我今天要解决的第一个问题。

看磁盘：够用但有讲究

三个盘,C 和 E 都比较宽裕。但虚拟机镜像必须放E 盘，放C 盘会占掉系统盘空间，容易出各种莫名其妙的故障。

坑点：D 盘只剩 34.5GB，如果之前打算放 D，立刻改。虚拟磁盘文件动辄几十 GB，D 盘撑不了几个 VM。

看虚拟化：VirtualBox 太老了

问题不大，但对K8s 集群有兼容麻烦：

问题 具体表现
内核模块过旧 Linux 5.x/6.x 内核的节点用不了部分虚拟化特性
网络稳定性差 etcd 对网络时延敏感，容易出现 leader 频繁切换
快照管理弱 不能分组命名，做故障演练很痛苦

而且发现机器上 VMware 只剩个 VMware VIX 残留组件，没有 Workstation 主程序。

决定装 VMware Workstation Pro 17。理由就一条：快照功能。

运维工程师最重要的自我保护习惯是”随时能回到干净状态”。你的实验室就是随时能回滚，这是真实生产环境没有的自由。

二、算一笔账：32GB 到底能跑多少

别急着装，先算清楚需求。

K8s 三节点集群（1 master + 2 worker）的最低内存需求：

组件 最低内存 说明
master 控制面 2GB etcd + apiserver + scheduler
worker × 2 各 2GB kubelet + kube-proxy + 容器运行时
剩余给系统 各 1GB 操作系统基础开销

理论最低 10GB。但这只是”能启动”的数字，实际跑应用会不够。

再看完整靶场的需求：

加上宿主机要给 Windows + WorkBuddy 留 8GB，32GB 最多只能分给 VM 20GB 左右。

这就推出了核心结论：同一时刻最多跑两层。

ELK 必须单独放一台 VM，因为 Elasticsearch 的 JVM 内存一旦和其他组件抢机器，整台都会卡死。

三、定下来的架构

为什么用 Host-only 网络

三种网络模式对比：

模式 宿主机访问 VM VM 上外网 VM 互通 结论
桥接 ✅ ✅ ✅ ❌ 会和公司办公网混，IP 可能冲突
NAT ❌ 需端口转发 ✅ ✅ ❌ 宿主机访问 VM 很麻烦
Host-only ✅ 方便 ❌ ✅ ✅ 完全隔离，不污染办公网

选 Host-only 的理由：

  1. 宿主机可以直接 SSH，不用每次查端口映射
  2. 完全隔离，不会因为搭靶场导致公司网络出问题
  3. 符合真实交付环境 —— 客户内网本来就是隔离的

唯一的代价是 VM 不能直接上外网装软件。解决办法是在宿主机下载好 deb/rpm 包，用 scp 传进去。这个限制反而是个福利——顺便练了”离线安装”这项交付技能，很多政企客户内网环境就是这么干的。

磁盘要”按需增长”

VM 磁盘上限设 80GB / 60GB / 60GB，但不要预先占满。VMware 建 VM 时选”按需增长”，实际初始只占 10-15GB。

很多人新建 VM 时勾了”立即分配所有磁盘空间”，三个 VM 立刻吃掉 200GB。这就是为什么我的磁盘规划要这么抠。

四、VT-x：不开就是白菜

K8s 用容器，但虚拟机本身依赖 CPU 硬件虚拟化。Intel 叫 VT-x，AMD 叫 AMD-V。

你的 Alder Lake 芯片硬件绝对支持，只差 BIOS 里那个开关。

确认方法：Ctrl+Shift+Esc → 性能 → CPU → 右下角看”虚拟化:”

如果显示”已禁用”，开机狂敲 Del 或 F2 进 BIOS，找 Intel Virtualization Technology 设为 Enabled。

判断 VT-x 是否生效还有个间接方法：我查注册表的 HypervisorPresent 键，返回”not found”就说明虚拟化层没起来。

五、今天的收获

1. 动手之前先算账。 运维和开发最大的区别是，运维的每一个决策都有资源成本。盲目开始装一堆东西，最后发现机器扛不住，浪费的不只是时间。

2. 工具版本会咬人。 VirtualBox 6.x 跑 K8s 集群会有各种玄学问题，不是你配错了，是工具老了。选对工具比硬扛更快。

3. 架构要按资源倒推。 不是”我想搭什么”而是”32GB 能搭什么”。32GB 的天花板决定了最多同时跑两层，这个约束反而让架构更清晰。

4. 限制也是学习机会。 VM 不能上外网，顺带练了离线安装；内存不够同时跑所有组件，顺带理解了为什么真实生产要做服务拆分和分层。

下一步开始动手：清内存、装 VMware、建三台 VM、打通 SSH 批量管理通道，然后正式进入中间件实战。

这个系列我会持续更新，每一阶段都会写踩坑记录。你也在学云原生的话，一起交流。
